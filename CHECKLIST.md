# Чек-лист проекта

## Перед релизом

- [ ] `VERSION`, `sw.js` и `index.html` совпадают (`tools/check-version.py`).
- [ ] `tools/check-modules.py` проходит.
- [ ] `node selftest.js` проходит без ошибок.
- [ ] `npm run smoke` проходит, включая Pyodide.
- [ ] Офлайн-архив пересобран и открывается локально.
- [ ] Проверены desktop и mobile: нет горизонтальной прокрутки.
- [ ] Обновлены `CHANGELOG.md` и описание версии.

## Новый модуль

- [ ] Файл добавлен в `index.html` в правильном порядке.
- [ ] Файл добавлен в `ASSETS` в `sw.js`.
- [ ] Файл добавлен в `FILES` в `tools/make-offline.py`.
- [ ] Если модуль нужен selftest — добавлен в `selftest.js`.
- [ ] Экспорт и зависимости описаны в `ARCHITECTURE.md`.
- [ ] Есть fallback, если зависимость ещё не загрузилась.

## Контент

- [ ] У вопроса ровно один правильный вариант.
- [ ] Формулы и числа проверены по данным.
- [ ] Нет двусмысленных формулировок и «правильного ответа по мнению».
- [ ] У главы есть шпаргалка, источники и связь с практикой.
- [ ] Примеры не раскрывают ответы автопроверок.

## UX и доступность

- [ ] Основная задача страницы видна без прокрутки.
- [ ] Кнопки имеют понятный текст, а не только иконку.
- [ ] Фокус и клавиатура работают в тестах и формах.
- [ ] Мобильная ширина 360–390 px не ломает сетку.
- [ ] Долгие операции показывают статус (Pyodide, загрузка данных).

## Dbt и данные

- [ ] `dbt build` проходит локально на Python 3.12.
- [ ] `dbt source freshness` запускается только на реальных данных.
- [ ] Синтетические seeds не выдаются за production freshness.
- [ ] Витрины и дашборд используют один и тот же расчёт.

## Стоп-условия

- Не добавлять новые разделы, пока mastery и проверки не станут убедительными.
- Не разрезать `app.js` дальше без реальной необходимости.
- Не добавлять зависимость без lock-файла и проверки в CI.
- Не выпускать версию с красным smoke или незакрытым regression.
