# Лаборатория аналитики

Учебник, тесты и тренажёры по данным, аналитике, статистике, теории игр, вероятности, SQL, Excel, Python, машинному обучению, AI/LLM, маркетингу, симуляциям, временным рядам, причинному выводу, этике и приватности. Статический сайт без сборки и бэкенда.

Сайт: https://chipsfirst.github.io/analytics_lab/

## Быстрый старт

```bash
python3 -m http.server 8123
# http://localhost:8123
```

Офлайн: скачайте `analytics-lab-offline.zip`, распакуйте и запустите `start.command` (macOS/Linux) или `start.bat` (Windows). Либо откройте сайт и установите его как приложение.

## Правки и проверка

Контент правится в `js/topics/<раздел>.js`. После изменений:

```bash
node selftest.js
python3 tools/check-version.py
python3 tools/make-offline.py
```

Версия хранится в `VERSION`; она продублирована в `sw.js` и `index.html`, а `check-version.py` проверяет совпадение. Пуш в `main` запускает проверку и деплой GitHub Pages.

## Ограничения

- Python-песочница при первом запуске скачивает Pyodide — нужен интернет.
- SQL-песочница не работает через `file://`: нужен локальный сервер из архива.
- Прогресс хранится в браузере; для переноса есть экспорт и импорт JSON.
- Большой, открытый и dbt-проекты синтетические: 27–29 тысяч строк и четыре таблицы, но реальные выгрузки грязнее и сложнее по схеме. В открытом проекте нет автопроверки: оценивать себя придётся по рубрике. Для dbt нужен Python 3.12: на 3.14 установка `dbt-duckdb` не собирается. Дашборд на сайте читает статические `mart_*`, а не подключён к BI-инструменту; `_loaded_at` в учебных данных фиксированный. `marketing.csv` даёт 90 дней и подходит для знакомства с временными рядами; для полноценного прогноза нужен более длинный ряд.
- Mastery в прогрессе — эвристика 40/40/20, а не валидированная метрика; её веса ещё нужно калибровать.
- Pandas-кейс проверяет дубли, даты, сумму и доли когорт, но полный эталонный прогон чек-ячейки в CI пока не автоматизирован.
- Smoke покрывает ключевые страницы и базовые интеракции, но не все формы, проекты и сценарии Pyodide.
- Архитектура использует глобальные контракты и ручной порядок скриптов; `check-modules.py` ловит рассинхронизацию, но не заменяет ES-модули.
- Dbt freshness запускается локально: синтетические seeds с фиксированным `_loaded_at` не годятся для честной CI-проверки.
